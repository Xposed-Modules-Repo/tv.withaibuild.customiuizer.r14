# Duo 三合一状态栏

正式构建版本：`r14.21.13` / versionCode `222`。稳定源码基线：`e4daedd4d9c0c5d72abef16521f2eb6e59d4b71c`（r14.21.9），保留后续的状态栏、设置、应用列表与计步修复。

入口：系统 → 状态栏 → Duo 三合一状态栏。默认关闭；开启、关闭、修改百分比、耳机提示、线条加粗或尺寸后需重启系统界面。

外圈显示电量，顶部显示百分比或充电闪电，中间显示 Wi-Fi（可选在耳机连接时替换为耳机），下方四点显示默认数据卡的蜂窝强度。充电为绿色、省电为黄色、低于 20% 为红色，其余跟随原生电池文字颜色。Wi-Fi 已连接但网络未验证时保留 `!` 提示；飞行模式关闭蜂窝点，仍可显示重新开启的 Wi-Fi。

本实现参考 [Duo Status Bar](https://github.com/kvmy666/duoStatusBar/tree/b7201384cc04c152576553d50d8fe5ddd4430cb0) 的[几何说明](https://github.com/kvmy666/duoStatusBar/blob/b7201384cc04c152576553d50d8fe5ddd4430cb0/docs/DESIGN-duo.md)，并核对其实际效果图。该项目的[参考说明](https://github.com/kvmy666/duoStatusBar/blob/b7201384cc04c152576553d50d8fe5ddd4430cb0/docs/references.md) 指向 [Status Trio](https://github.com/lingyired/status-trio)。这里独立编写 Canvas 绘制和 HyperOS 1 的集成，不引入其 Rive、Compose、字体、媒体资源或动画系统。

## 尺寸、区域与显示规则

- 自动尺寸默认开启：原生 `status_bar_icon_height` × 1.1，限制为 20–24dp；原生尺寸缺失时使用 22dp。绘制仍受宿主行高约束。本机原生高度约 20.36dp，自动分配 65px，旧 28dp 为 81px，宽度约减少 20%。
- 关闭自动尺寸后使用原有手动值，范围 20–40dp，新安装默认 24dp。升级不覆盖保存的手动值；自动开启时手动滑块禁用。
- 普通状态栏、锁屏与控制中心共用一个状态来源和绘制实现。控制中心宿主是 SystemUI 的 `ControlCenterStatusBarIcon`，无需在插件加载器中另建实现；宿主不存在时仍支持普通状态栏。
- 耳机提示默认开启，可单独关闭。有线连接沿用原生策略已有接收器及其聚合连接表；蓝牙沿用控制器已经准备的连接、音频类型和活动状态。鼠标等非音频蓝牙连接不会误显示为耳机。
- 中间图案优先级：Wi-Fi 网络异常 → 无 Wi-Fi 的飞行模式 → 有线耳机 → 蓝牙音频 → Wi-Fi。蓝牙音频在新连接时用简洁蓝色耳机提示 3 秒，然后恢复网络图案；移除耳机旁的蓝牙标记。有线耳机保持显示。初始同步、重复事件与宿主重新附着不重播或延长蓝牙提示。表示连接状态，不声称当前媒体路由。
- 可选线条加粗默认关闭：电量圆环从 8 增至 10 个绘制单位，Wi-Fi／耳机从 7 增至 9，不扩大图标尺寸或修改原生文字样式。
- 原生耳机、蓝牙、静音等独立图标仍按原有设置显示，保证中间显示网络警告时这些状态依然可见。Duo 只替换电池子视图、Wi-Fi 和蜂窝信号视图。
- Duo 的百分比、尺寸独立于原生电池隐藏／样式；信号左移、交换顺序和双排继续控制原生布局，Duo 跟随电池宿主的位置与行高。原生设置不写回或覆盖 Duo 键；失败回退后保留原生设置的显示意图。

[Status Trio](https://github.com/lingyired/status-trio) 面向 macOS，中间还能显示音量及蓝牙音频设备。本实现参考其连接状态与网络警告优先的思路，独立绘制 Android 耳机图案，继续保留底部蜂窝信号，不加入 macOS 权限、媒体资源或轮询。

## 开销与所有权

- 沿用 Feature 的 SystemUI / PACKAGE_READY 安装入口和 API 101 安全边界；关闭时不解析 ROM 字段，不创建业务 Hook、视图、Handler、Receiver 或 Observer。
- 开启后旁路读取原生电池、网络、蓝牙控制器、耳机策略与 CallbackHandler 的现有事件，不改参数、原生状态或调用次数。
- 字段与方法只在安装时解析。电池和网络使用原子可见的整数快照，双卡状态仅有两个物理槽位；未知状态不冒充零强度。
- 相同状态不触发刷新；后台事件至多排入一个待处理的主线程刷新。无轮询、动画循环、新服务或线程。蓝牙连接提示额外最多一个 3 秒到期任务；最后一个宿主释放或失败时取消，已连接状态不反复投递。
- 四个宿主弱引用、每个宿主最多八个信号视图。原生图标组替换时移除失效引用；视图脱离时恢复并释放原生子视图。
- 绘制使用预建 Paint、Path 与固定几何。帧内不创建字符串、数组或集合；数字字符串只在电量变化时更新。
- 原生电池宿主承载图标，继承原有位置、可见性、淡出与父布局；尺寸遵守原有行高和测量约束，不修改 Insets、窗口高度或 Dynamic Island。

## 回退与验证边界

必需的类、方法、字段不匹配时，不安装替换；部分安装失败时撤销已经安装的 Hook。电量、Wi-Fi 或默认数据卡状态不完整时，保留原生图标。可选音频 ABI 不匹配或音频回调异常只停用耳机提示。电池／网络运行或绘制异常使该进程的 Duo 回退到原生显示；致命错误按项目规则继续抛出。

自动测试覆盖未知状态、双卡默认数据卡切换、无服务、订阅移除与旧回调、飞行模式与 Wi-Fi 共存、网络未验证、重复事件、并发写入、圆环映射、原生可见性恢复和默认关闭的 Feature 接线。

2026-10-03 从连接的 fuxi（HyperOS 1 / Android 14，V816.0.7.0.UMCTWXM）提取 SystemUI，SHA-256 为 `5d8f2fe0b65d8a1a947b4280f8053b524f8c5de73f48a74f8792d415ae76e513`。发现 r14.21.10 错用了 AOSP Wi-Fi 控制器名，且通过 `cleanState()` 的基类返回类型解析移动状态，导致安装前接口检查失败。r14.21.11 改用 `statusbar.policy.MiuiWifiSignalController`、其 `WifiState` 与 `statusbar.SignalIcon$MobileState`；不调用 `cleanState()`，不增加运行时探测或任务。手写 JVM 接口替身覆盖完整解析、继承字段、类型擦除、缺失类回退和致命错误传播。

本地 JVM、静态门禁、lint 与正式签名构建不能替代目标 HyperOS 1 实机验收。ROM 接口已核对，r14.21.11 在本机锁屏／桌面显示已复现，并确认控制中心尚为原生图标。r14.21.13 的逐项验收和签名产物信息由本次交付验证报告记录；长期耗电与帧率不能由短时验收推定。

实机收口需检查：桌面 / 应用 / 锁屏 / 控制中心、深浅背景、横屏、双排状态栏、信号左移、默认数据卡切换 / 拔卡、有线／蓝牙耳机连接与断开、Wi-Fi 断连 / 无互联网、飞行模式 / 充电 / 省电、关闭后重启恢复原生显示，以及重复解锁 / 旋转后的视图数量、内存和 SystemUI 日志。
